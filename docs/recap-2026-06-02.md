**Date:** 2026-06-02  
**Prepared by:** portal admin
**Period covered:** 2026-05-18 → 2026-06-02

## What We Built

The IWS MIS Portal is an internal portfolio management system for IWS Finserv and its 6 linked entities (DHR, ADR, IWS, HHR, IWSFC, SDR). It automates the daily ingestion of Consolidated Account Statements from CAMS, parses them into PostgreSQL, enriches the data with live NAVs, equity prices, and FX rates, and presents everything through a Next.js dashboard. The project went from nothing to a fully automated, production-running system in roughly two weeks.

## Phase 1 — Core Portal (2026-05-18 to 2026-05-25)
*Pre-git. Work was done locally and pushed to GitHub on May 26.*

Built the entire foundation of the portal from scratch:

### Backend — `mis-portal/main.py` (FastAPI, 455 lines at first commit)

- FastAPI application with PostgreSQL connection pool (`psycopg2.pool.ThreadedConnectionPool`)
- Redis integration for token blacklist and rate-limit state
- JWT-based authentication with httpOnly cookie transport
- `/api/v1/login` — bcrypt password verification, JWT issue, audit log write
- `/api/v1/logout` — token revocation via Redis blacklist
- `/api/v1/me` — session introspection; `is_active` check
- `/api/v1/health` — liveness endpoint; checks token blacklist so it can't be used to probe Redis state
- Rate limiting via `slowapi` — keyed on `X-Forwarded-For` (later fixed to `CF-Connecting-IP`)
- Account lockout after failed login attempts
- CORS scoped to `iwsfinserv.com` only
- Graceful shutdown via `atexit` to close DB pool and Redis connections

### Frontend — `iws-portal-frontend/` (Next.js)

- Login page replaced the default Next.js home — form with email + password, loading spinner, error state
- Dashboard at `/dashboard` — session-gated, shows user profile and basic portfolio stub
- Auth entirely via httpOnly cookie (`credentials: include` on all fetch calls) — no localStorage token handling
- Skeleton loading state, error state with fallback link on dashboard

### Infrastructure

- Nginx reverse proxy in front of both services
- PostgreSQL database with `mis_portal` schema
- Redis for token blacklist and rate limiting
- Deployed on Ubuntu (Hetzner) with systemd

## Phase 2 — Security Audit & Bug Fixes (2026-05-26)
*8 commits in one day. The portal was working but had several serious vulnerabilities discovered on first review.*

### Critical security fixes

| Bug | Impact | Fix |
|---|---|---|
| Rate limit keyed on `X-Forwarded-For[0]` | Attacker-controlled header — anyone could bypass brute-force protection by spoofing the IP | Changed to `CF-Connecting-IP` |
| Token blacklist fail-open | If Redis went down, `is_token_blacklisted()` returned `False` → logged-out tokens remained valid | Changed to fail-closed (deny on Redis unavailability); logout returns HTTP 503 if revocation fails |
| Lockout race condition | Parallel login requests could both read the same `failed_attempts` counter and both pass the lockout check | Replaced read-modify-write with atomic `UPDATE ... RETURNING` |
| bcrypt truncation | bcrypt silently ignores input past 72 bytes — two passwords sharing the same first 72 bytes were treated as identical | Capped `max_length` at 72 on both frontend input and backend validation |
| Audit log aborts connection | A failed `write_audit_log` INSERT left the DB connection in aborted state, causing the next successful login to 500 | Added `conn.rollback()` in the audit log exception handler |
| Logout silent failure | Frontend redirected to login regardless of whether the server revoked the token | Frontend now checks `res.ok` and shows an error if revocation failed (HTTP 503) |
| Legacy endpoint double rate-limit | `/api/v1/auth/login` called the new `_login_impl` but also had its own rate-limit counter | Extracted `_login_impl`, both endpoints share it without double-counting |

### CSP — nonce-based policy via `proxy.ts`

Added `proxy.ts` (a Next.js custom server wrapper) that:
- Generates a fresh nonce per request
- Injects `Content-Security-Policy` header with `script-src 'nonce-{x}' 'strict-dynamic'`
- Removes `unsafe-eval` and `unsafe-inline` entirely
- Scopes `connect-src`, `font-src`, `img-src` to match the existing nginx policy

Password `maxLength` on the frontend input fixed from 128 → 72 to match the backend.

### UI polish

Full design system overhaul of the login and dashboard:
- Replaced hardcoded gray/blue values with a semantic OKLCH token system: `page`, `card`, `ink`, `dim`, `ghost`, `prime`, `peril`, `wire`, `rule`, `muted` — each with light and dark variants
- `prefers-reduced-motion` respected throughout
- Skip-to-content link and proper landmark structure (`main#main-content`)
- Login: spinner during submission, inputs locked while submitting, hover/focus transitions, disabled-button contrast fix (opacity instead of muted background), `aria` labels on errors
- Dashboard: greeting toned down, sign-out restyled as secondary outline, profile section uses `dl/dt/dd` grid for aligned key-value layout, skeleton loading, inline error with fallback link

## Phase 3 — MF Holdings API + CAS Pipeline (2026-05-28)
*First feature work after the portal was secure and stable.*

### MF Holdings & Transactions API

- `GET /api/v1/holdings` — auth via `_require_auth`, admin can query any entity via `?entity_id=`, returns holdings grouped by asset class with live NAV and current value
- `GET /api/v1/transactions` — paginated, same auth/entity logic
- Fixed 404: admin users with no linked entity were returning 404 from both endpoints; now returns empty response so dashboard renders correctly
- Frontend holdings table: grouped by asset class, INR formatting, skeleton loader, inline error state

### CAS automation pipeline — built from scratch

Four new workers, ~1,000 lines total:

| Worker | Role |
|---|---|
| `cas_automation_worker.py` | Orchestrator — runs all 6 entities sequentially |
| `cams_trigger_worker.py` | Playwright headless — fills and submits CAMS CAS form |
| `gmail_worker.py` | Gmail API — polls central inbox (the central collector inbox), downloads PDFs |
| `cas_parser_worker.py` | PyMuPDF + casparser — decrypts, parses, upserts DB |

**Flow per entity:**
1. Generate random PDF password (`secrets.token_urlsafe(12)`)
2. Playwright fills CAMS form (email + PAN + password + Detailed + Since Inception)
3. Poll Gmail for incoming PDF, filter by alias (`to:` header)
4. Decrypt with entity's password, parse folios + transactions
5. Upsert `security_master`, `folio_mapping`, `holding`, `mf_transaction`

**Bug fixed on day one:** IWSFC entity was silently dropped — `NAME_PATTERNS` mapped `"iws fincorp"` but DB had `"IWS Fincorp"`. Case mismatch meant `entity_map.get("IWSFC")` always returned `None`.

## Phase 4 — Security Round 2 + CAMS Fixes + Dashboard UX (2026-05-29)

### Security hardening (second round)

| Item | Before | After |
|---|---|---|
| JWT lifetime | 30 days | 24 hours |
| Cookie `max_age` | Misaligned | Aligned to 24 h |
| Redis blacklist key | Raw JWT string | SHA-256 hash (prevents large-key DoS; stops raw token in Redis) |
| Login lockout threshold | 10 attempts | 5 attempts |
| Locked account response | Revealed remaining lockout time | Generic 401 (closes account enumeration) |
| Next.js bind address | `:::3000` (internet-exposed, bypassing nginx/Cloudflare) | `127.0.0.1` |
| Gmail OAuth credentials | Unprotected in repo | Added to `.gitignore` |
| CAMS screenshots | World-readable `/tmp` | `0700`-restricted directory |

### CAMS automation bug fixes

- **False OTP error:** CAMS was returning "unable to process your request" (rate-limit/bot rejection) but the code matched the word `"otp"` anywhere in the static page HTML and reported the wrong error. Fixed: added the real error string to the detector, narrowed OTP signals to `"enter otp"`, `"verify your email"`, `"one time password"`.
- **No form-fill confirmation:** no screenshot existed between "fields filled" and "submit clicked". Added a post-fill screenshot (`cams_postfill_*.png`) to confirm fields populated before Submit.
- **Sequential + 90 s cooldown:** parallel entity runs were triggering CAMS IP rate-limiting. Added cooldown between entities.

### CSP nonce bug fixed

`app/layout.tsx` was statically pre-rendered. `proxy.ts` injects the nonce on every request, but static pages had no nonce in their HTML → browser blocked all JS → infinite spinner on login and dashboard. Fixed with `export const dynamic = 'force-dynamic'`.

### Admin all-entity view

Admin user the relevant portal account had a stale `entity_id = 9` (IWS Finserv) in DB, so the holdings API scoped to that single entity. Fixed: nulled admin's `entity_id`; API now returns all entities when admin calls the endpoint without `?entity_id`. Each record includes `entity_name`.

### Dashboard UX overhaul

Scored 25/40 on Nielsen's 10 heuristics — three P1 issues resolved:
- **Donut chart** — pure SVG, `stroke-dasharray/stroke-dashoffset`. Three segments: Equity (amber), Fixed Income (indigo), Alternates (teal). OKLCH color tokens in `globals.css` (light + dark).
- **P&L summary row** — Total Invested + Current Value + Unrealized P&L. Only shown when all holdings have a NAV (`allHaveNav`) to avoid misleading partial totals.
- **Column sorting** — per asset-class group; preserves visual grouping. `SortKey`: Scheme, Invested, Current Value, Units. Default: Current Value descending. `aria-sort` on `<th>`.
- Profile card removed; data freshness line added under page `h1`.

### Path traversal vulnerability fixed (`gmail_worker.py`)

`_download_attachment()` used `os.path.join(save_dir, filename)` where `filename` was a sender-controlled value from the email attachment. A crafted `filename` (e.g. `../../etc/passwd`) could write outside `save_dir`. Fixed:
1. `os.path.basename(filename)` strips directory components
2. `re.sub(r"[^\w\-.]", "_", ...)` sanitizes remaining characters
3. Fallback to `cas_{msg_id}.pdf` if name doesn't end in `.pdf`
4. `os.path.realpath(save_path).startswith(os.path.realpath(save_dir) + os.sep)` confirms confinement; rejects and logs if check fails

## Phase 5 — Parallel CAS + Analytics Dashboard (2026-05-30)

### CAMS CDK backdrop bug

CAMS T&C dialog uses Angular Material. When PROCEED was clicked, the `mat-dialog-container` closed but the CDK backdrop (`cdk-overlay-backdrop`) remained. Playwright's actionability check then rejected all subsequent `locator.click()` calls on form inputs, raising "Could not find email field" for every entity. Fixed by waiting for the backdrop to detach before proceeding with form fill.

### CAS automation rewrite — parallel architecture

Old flow: trigger → wait 15 min for email → parse → next entity. 6 entities ≈ 90 min total.

New flow:
- One **Gmail collector thread** polls the central inbox every 30 s for all new CAS PDFs (subject filter: "Consolidated Account Statement")
- After each CAMS trigger, a **parser thread** starts immediately and waits for a PDF it can decrypt (`fitz.authenticate()` returns non-zero only for the matching password)
- All 6 parser threads run concurrently
- Wall time: ~15–30 min instead of ~90 min
- Gmail wait window: 15 min → 30 min

### Cron additions

| Job | Before | After |
|---|---|---|
| AMFI NAV worker | Mon–Fri only | Daily (weekends fetch last known NAV) |
| FX Rates worker | Not in cron | Added — 6 AM IST daily |

### Dashboard — major feature update

**Layout + open items cleared:**
- `max-w-4xl` → `max-w-6xl` (wider layout)
- Retry button on error state; Refresh link in holdings header
- Real-time search/filter by scheme name, folio, or entity name
- Sticky table headers on all three sections

**Admin features:**
- Entity switcher pill tabs (All / DHR / ADR / IWS / HHR / IWSFC / SDR)
- Entity column in all-entities view (holdings + transactions)

**Transactions section:**
Latest 100 transactions. Columns: Date / Scheme / Folio / Type (green = purchase/SIP, red = redemption) / Units / NAV / Amount. Fixed: admin all-entities view was returning empty — backend now returns transactions across all entities with `entity_name` per row.

**Portfolio Analytics section:**

| Part | What it shows |
|---|---|
| Summary strip | Total Invested / Current Value / Total Gain / Overall Return% / Fund count |
| Asset allocation donut | Equity / Fixed Income / Alternates with % bars |
| Fund breakdown bars | Horizontal bars scaled to largest holding, coloured by asset class |
| Arbitrage card | Separate card for `MF_ARBITRAGE` funds with per-fund Invested / Current / Gain / Return% / Weight% / CAGR |
| Performance detail table | All funds with full metrics, sticky headers, sortable |

CAGR formula: `(current_value / invested_amount) ^ (365.25 / days_held) − 1` using `first_invested_date` from DB. Not shown if investment < 60 days old.

## Phase 6 — Equity & MF Tracking + Security Round 3 (2026-06-01)

### CAS schedule randomisation

Engine starts at 11 PM IST (cron `30 17`). Gmail collector now scans until 8 AM IST (up from 30 min) so late-arriving PDFs are never missed.

Trigger order shuffled each night so no two consecutive entities share the same PAN — prevents CAMS blocking the 3rd same-PAN request. Inter-trigger delay is double-randomised: a ceiling is drawn uniformly from 45–75 min, then the actual delay is drawn from 30 min to that ceiling — making the pattern unpredictable across nights.

### Equity holdings module — new package (`mis-portal/equity/`)

Three broker adapters normalise holdings into a common `EquityHolding` model:

| Adapter | Broker | API |
|---|---|---|
| `zerodha.py` | Zerodha / Kite | Kite Connect REST |
| `angel_one.py` | Angel One | SmartAPI |
| `dhan.py` | Dhan | Dhan Holdings API |

New DB tables: `equity_holding` (live snapshot) and `equity_holding_history` (daily EOD snapshots for weekly/YTD P&L anchors).

**Equity sync worker** (`equity_sync_worker.py`) runs daily at 7 AM IST. Per entity + broker: fetches holdings, normalises, computes all metrics, upserts `equity_holding`, writes daily snapshot to `equity_holding_history`.

**Token refresh worker** (`token_refresh_worker.py`) runs at 6:30 AM IST — refreshes broker API access tokens before the sync runs.

### Live equity price worker (`workers/equity_price_worker.py`)

Runs every minute during market hours (09:15–15:30 IST, Mon–Fri). Fetches live LTP from all three brokers, recomputes all derived metrics in-place. Writes EOD snapshot in the last 5 min before market close (15:25–15:30).

### MF metrics worker (`workers/mf_metrics_worker.py`)

Runs at 10:15 PM IST after `amfi_nav_worker`. Reads NAV already stored on each holding row, fetches historical NAV anchors from `nav_history`, and writes computed metrics back to `holding`:

| Metric | Source |
|---|---|
| `market_value_as_on` | `quantity × last_updated_nav` |
| `prev_week_value` | `quantity × closest NAV ≤ last Friday` |
| `weekly_change` | `market_value_as_on − prev_week_value` |
| `exposure_pct` | `market_value_as_on / entity total MF value × 100` |
| `pnl_inception` / `pnl_ytd` | Cost basis vs current, fiscal year anchor = Apr 1 |
| `returns_inception_pct` | `pnl_inception / cost_basis × 100` |
| `cagr_inception_pct` | `(current/cost)^(1/years) − 1` |

### NAV history backfill (`workers/nav_history_backfill.py`)

One-shot script. Backfills `nav_history` from AMFI historical data so the MF metrics worker has enough anchors for CAGR and YTD calculations on day 1.

### Frontend — two new pages

| Route | Key columns |
|---|---|
| `/equity` | Symbol / Qty / Avg Cost / LTP / Current Value / P&L / Return% / Exposure% / Weekly Δ / YTD P&L |
| `/mutual-funds` | Scheme / Folio / Units / Cost / Current Value / P&L / Return% / Exposure% / Weekly Δ / YTD P&L / CAGR |

Dashboard updated with quick-link cards to both new pages.

### `holding` table extended

Added metric columns to match equity layout: `market_value_as_on`, `as_of_date`, `prev_week_value`, `weekly_change`, `exposure_pct`, `pnl_inception`, `pnl_ytd`, `pnl_weekly_change`, `returns_inception_pct`, `returns_ytd_pct`, `cagr_inception_pct`. `first_invested_date` now preserved on UPDATE via `COALESCE(first_invested_date, %s)`.

### Security hardening (third round)

- CSP/security-headers middleware promoted from `proxy.ts` → `middleware.ts` (active in all environments)
- FastAPI `openapi.json` and `redoc` endpoints suppressed in production
- JWT lifetime: 24h → 2h; `/api/v1/auth/refresh` endpoint added
- `GET /api/v1/entities` now enforces admin role check
- Equity broker token files written with `os.chmod(0o600)`
- `seed_users.py` — removed plaintext password `print` statement
- Login error response normalised across all paths (closes user enumeration)
