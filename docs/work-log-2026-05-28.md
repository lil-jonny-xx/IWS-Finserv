## 2. CAS Automation Pipeline (workers built today)

Built full end-to-end CAS ingestion pipeline:

| File | Role |
|---|---|
| `cas_automation_worker.py` | Orchestrator — runs all 6 entities sequentially |
| `cams_trigger_worker.py` | Playwright headless → submits CAMS CAS form |
| `gmail_worker.py` | Gmail API → polls central inbox, filters by alias `to:`, downloads PDF |
| `cas_parser_worker.py` | PyMuPDF + casparser → parses PDF, upserts DB |
| `oauth_setup.py` | Gmail OAuth2 setup helper |
| `db_migrate_entities.py` | DB migration for entity table |

**Flow per entity:**
1. Generate random PDF password (`secrets.token_urlsafe(12)`)
2. Playwright fills CAMS form (email + PAN + password + Detailed + Since Inception)
3. Poll central Gmail inbox up to 15 min, filter `to:<alias>`
4. Parse PDF with same password → extract folio→holder map via PyMuPDF regex
5. Map holder name → entity via `NAME_PATTERNS`
6. Upsert `security_master`, `folio_mapping`, `holding`, `mf_transaction`
7. `ON CONFLICT DO NOTHING` handles duplicate folios across entities (ADR appears in DHR's CAS)
8. After all entities: refresh NAVs via `amfi_nav_worker`

**Scheduled:** cron `30 21 * * *` (3 AM IST daily)
