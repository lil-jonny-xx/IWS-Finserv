## 1. CAS Automation — Debugging & Parallel Rewrite

### What was wrong

Ran the automation manually for the first time. Three problems found:

- **False OTP error** — CAMS returned "unable to process your request" (rate-limit/server rejection), but the code was detecting the word "otp" somewhere in the static page HTML and reporting the wrong error. Made it impossible to tell the real cause.
- **Form fill not confirmed** — no screenshot existed between "fields filled" and "submit clicked", so when failures happened there was no way to know if the form was actually filled.
- **IP rate-limiting** — ran 5–6 manual test runs in under 2 hours. CAMS blocked the server IP for the rest of the day. Nightly cron (one run per day) should not hit this.

### Fixes to `cams_trigger_worker.py`

1. Added `"unable to process your request"` to the error detector — now caught *before* the OTP check so the right error shows up.
2. Removed bare `"otp"` from OTP signals (too broad). Now only triggers on `"enter otp"`, `"verify your email"`, `"one time password"`.
3. Added a **post-fill screenshot** (`cams_postfill_*.png`) saved right before Submit — confirms fields were populated before the request goes out.

### Tried Tor for IP masking

CAMS blocks all Tor exit nodes (standard for Indian financial portals). Reverted. Direct connection is fine for the nightly cron.

### Parallel rewrite of `cas_automation_worker.py`

Old flow: trigger entity → wait 15 min for email → parse → next entity. Six entities = ~90 min total.

New flow:
- One **Gmail collector thread** polls the central collector inbox every 30 seconds for new CAS PDFs, using subject filter (`Consolidated Account Statement`) instead of a per-entity `to:` filter.
- After each CAMS trigger, a **parser thread** starts immediately and waits for a PDF that opens with its entity's unique password (`fitz.authenticate()` returns non-zero only for the correct password).
- All 6 parser threads run at the same time.
- Total time: ~15–30 min instead of ~90 min.
- Gmail timeout increased from 15 min → 30 min.

Also added `collect_new_cas_pdfs()` to `gmail_worker.py` — one-shot poll that returns all new CAS PDFs since run start, filtering by message ID to avoid re-downloading.

## 3. Dashboard — Major Feature Update

### Layout & UX fixes (open items cleared)

- **Wider layout** — `max-w-4xl` → `max-w-6xl`
- **Retry button** — holdings error state now has a Retry button. Also a Refresh link in the holdings header. Both re-fetch holdings and transactions together.
- **Search / filter** — text input above the holdings table filters by scheme name, folio number, or entity name in real time.
- **Sticky table headers** — column headers stay fixed while scrolling, like Excel freeze row. Applied to holdings, transactions, and analytics tables.

### Admin features

- **Entity switcher** — pill tabs at the top (All / DHR / ADR / IWS / HHR / IWSFC / SDR). Clicking a tab scopes both holdings and transactions to that entity. Works off `/api/v1/entities`.
- **Entity column** — when admin is in "All Entities" view, a new Entity column appears in the holdings table showing which mutual fund belongs to which entity. Sortable.

### Transactions section

New section below holdings showing the latest 100 transactions. Columns: Date / Scheme / Folio / Type (colour-coded — green for purchase/SIP, red for redemption) / Units / NAV / Amount. Admin all-entities view adds an Entity column.

Backend: admin transactions API was returning empty for the all-entities view. Fixed — now returns all transactions across all entities with `entity_name` per row.

### Portfolio Analytics section

New section between holdings and transactions, computed entirely from existing holdings data (no new API call).

| Part | What it shows |
|---|---|
| Summary strip | Total Invested / Current Value / Total Gain / Overall Return% / Fund count |
| Asset allocation donut | Equity / Fixed Income / Alternates breakdown with % bars |
| Fund breakdown bars | Every fund as a horizontal bar scaled to the largest holding. Width = % of portfolio. Colour by asset class. |
| Arbitrage funds | Separate card section — triggered automatically when any `MF_ARBITRAGE` fund exists. Shows Invested / Current / Gain / Return% / Weight% / CAGR p.a. per fund. Note: ICICI Pru EqSaving (equity savings) falls here per BAS classification. |
| Performance detail table | All funds with: Invested / Current Value / Gain+Loss / Return% / Weight% / CAGR p.a. Sticky headers, sortable implied by existing sort logic. |

**CAGR formula:** `(current_value / invested_amount) ^ (365.25 / days_held) − 1`, using `first_invested_date` from the DB. Matches the "CAGR (Inception)" column in `bas.xlsx`. Not shown if investment is less than 60 days old.

**BAS file reference** (`/var/www/bas.xlsx` — Individual sheet): columns used as reference: EXPOSURE (%), CURRENT MARKET VALUE, COST, P&L, RETURNS, CAGR (Inception). All computed from DB — BAS used for column naming and fund categorisation only.
