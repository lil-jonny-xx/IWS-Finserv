## 1. Realized Gains — Backend (`mis-portal/main.py`)

### New helper — `_compute_realized_gains()`

Computes realized capital gains per `(entity_id, security_id, folio_number)` using the **average cost method**.

| Transaction type | Effect |
|---|---|
| `PURCHASE`, `PURCHASE_SIP`, `SWITCH_IN`, and any inflow with `units > 0 && amt > 0` | Adds to running units + cost |
| `STAMP_DUTY_TAX` | Adds to cost basis only (no units) |
| `REDEMPTION`, `SWITCH_OUT` | `gain += proceeds − redeemed_units × avg_cost`; reduces running units + cost |

Returns a `dict` keyed by `(entity_id, security_id, folio_number) → float`.

### `/api/v1/holdings` endpoint expansion

Both the all-entities and per-entity branches of `GET /api/v1/holdings` now:
- JOIN `pan_group` to expose `pan_group_name`
- SELECT all MF metrics columns written by `mf_metrics_worker` (`market_value_as_on`, `as_of_date`, `prev_week_value`, `weekly_change`, `exposure_pct`, `pnl_inception`, `pnl_ytd`, `pnl_weekly_change`, `returns_inception_pct`, `returns_ytd_pct`, `cagr_inception_pct`)
- Call `_compute_realized_gains()` and attach `realized_gain` per holding row

Previously the endpoint only returned `nav` / `current_value` and left clients to derive everything else.

## 2. CAS Parser Bug Fix — `workers/cas_parser_worker.py`

`upsert_holding()` UPDATE statement extended with:

```sql
first_invested_date = COALESCE(first_invested_date, %s)
```

Previously, re-importing a CAS PDF would overwrite `first_invested_date` with `NULL` on existing holdings (the column wasn't in the UPDATE). Now the date is preserved once set.

## 3. Dashboard — Column Filters & Realized P&L (`app/dashboard/page.tsx`)

### New `ColFilter` component

Reusable click-to-filter dropdown that sits inline in a table column header. Renders a `▾` chevron when inactive and the selected value when active. Closes on outside click. Aligns left or right based on `align` prop.

### Holdings table (`HoldingsSection`)

- **Type filter** — dropdown in the Scheme header, values derived from `security_type` labels
- **Entity filter** — dropdown in the Entity header (admin view only)
- **Folio filter** — Folio header replaced with a `ColFilter` dropdown
- Filters are applied after text search; both can be active simultaneously

### Analytics table (`AnalyticsFundTable`)

- "Gain / Loss" column split into **Unrealized** and new **Realized** column
- Summary stat strip: "Total Gain / Loss" renamed → **Unrealized P&L**; new **Realized P&L** card shown when non-zero
- Fund detail rows (mobile card view) also show Realized when non-zero
- Type and Entity column filters added
- `colSpan` updated from 9 → 10

### Transactions table (`TransactionsSection`)

- **Type-filter pill bar** in the card header: All / Purchase / Redemption / Switch / Dividend / Stamp Duty
- `TXN_TYPE_GROUPS` constant maps display labels to raw DB transaction types (`PURCHASE + SIP` → "Purchase", etc.)
- Pill tabs only render if that type exists in the current dataset
- Entity and Folio column-header dropdowns
- Row count changes to `"N of M total"` when a filter is active
