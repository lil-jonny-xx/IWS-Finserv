## 3. Equity History Backfill (`equity/equity_history_backfill.py`)

New standalone script to populate `equity_holding_history` for key dates so that computed metrics in `equity_holding` are non-NULL:

- **Last completed Friday** → `prev_week_value`, `weekly_change`, `pnl_weekly_change`
- **FY start (April 1)** → `pnl_ytd`, `returns_ytd_pct`
- Uses `kite.instruments('NSE')` to build `symbol → instrument_token` map
- Uses `kite.historical_data(token, from, to, "day")` for closing prices
- Inserts into `equity_holding_history` with `ON CONFLICT DO UPDATE`
- Calls `recompute_metrics()` which runs `compute_metrics()` and UPDATEs `equity_holding`
- **Result:** 44/45 DHR symbols backfilled (SGBAUG28V SGB skipped — no NSE EQ token)

## 4. New API Endpoints (`mis-portal/main.py`)

### `GET /api/v1/equity/holdings`

Returns all `equity_holding` rows for the authenticated entity (or all entities for admin), with:
- All computed metrics (`prev_week_value`, `pnl_ytd`, `cagr_inception_pct`, etc.)
- Broker grouping metadata
- `totals` object (total cost, market value, P&L)

### `GET /api/v1/overview`

Aggregates **all asset classes across all entities** for the portfolio summary dashboard:

```json
{
  "summary": {
    "total_invested", "total_value", "total_pnl",
    "total_pnl_ytd", "total_weekly", "weighted_cagr"
  },
  "asset_class_breakdown": [
    {"class": "DIRECT_EQUITY", "value": ..., "pct": ...},
    {"class": "MF", ...}
  ],
  "entities": [
    {
      "entity_id", "entity_name", "total_value",
      "breakdown": [{"class": ..., "value": ..., "pct": ...}]
    }
  ]
}
```

MF data sourced from `holding` table; equity from `equity_holding`.

## 7. Zerodha Trade Book CSV Importer (`equity/zerodha_tradebook_import.py`)

New CLI script to backfill `first_invested_date` from a downloaded Zerodha Console Trade Book CSV:

- Auto-detects column names across Zerodha's common CSV variants (`tradingsymbol`/`symbol`, `trade_date`/`order_execution_time`, `trade_type`/`transaction_type`)
- Finds the **earliest buy date** per `tradingsymbol` in the CSV
- Matches against `equity_holding` rows (by entity + symbol)
- Updates `first_invested_date` only where the CSV date is **earlier** than the current DB value (or where it's NULL)
- Dry-run mode (`--dry-run`) prints what would change without touching the DB
- Usage: `python equity/zerodha_tradebook_import.py --entity DHR --file tradebook.csv`

**Why this matters:** CAGR (`cagr_inception_pct`) requires `first_invested_date`. On first sync the column defaults to today, making CAGR NULL until ≥0.08 years pass. Importing the trade book sets the real purchase date retroactively.
