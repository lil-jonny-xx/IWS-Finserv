## Jarvis Assistant — Model Routing + Effort Tuning

### `assistant/routing.py` (new)
- `choose_model(user_text, history)` — Sonnet 4.6 by default, escalates to Opus 4.8 for advisory/analytical questions (keyword heuristic: "should I", "recommend", "valuation", "why is X lagging", …) or long multi-part messages. Deterministic, no extra classifier call, no added latency
- `effort_for(model)` — pairs reasoning effort with tier; both default to `medium` (was hardcoded `high`). Thinking tokens bill as output → second-biggest cost dial after model choice
- Model ids + effort levels env-tunable (`ASSISTANT_MODEL_*`, `ASSISTANT_EFFORT_*`)

### `assistant/engine.py`
- Uses `choose_model` per user turn (reused across the agentic loop); chosen model emitted on the `done` event for cost attribution

### `assistant/tests/test_routing.py` (new)
- 17 cases: simple→default, advisory→escalation, long-message escalation, env override, effort pairing

**Cost impact:** routing + medium effort takes blended cost from ~$0.60/msg (all-Opus) to ~$0.35/msg; heavy usage ≈ $630/mo.

## Equity — "Since" Date + Live-Refresh Fixes
*(branch `fix/equity-since-live-refresh`)*

### `equity/equity_sync_worker.py` — Since-date bug
- **Root cause:** `first_invested_date` was defaulted to **today** on first insert → wrong "Since" date and a bogus ~0-year CAGR
- **Fix:** leave it `NULL` until the real purchase date is known. "Since" renders "—" and CAGR is skipped until backfilled from the broker tradebook (`zerodha_tradebook_import.py`) — honest instead of wrong

### `app/equity/page.tsx` — refresh wiping table state
- **Bug:** the 60s auto-refresh called `setLoading(true)` every tick, swapping the table for the skeleton and **unmounting `EquityTable`** — resetting the user's sort, filters, and search
- **Fix:** skeleton only on first load (`didInitialLoad` ref); background refreshes update values in place with the table mounted. A failed refresh keeps last-loaded values with a quiet notice instead of the full error screen
