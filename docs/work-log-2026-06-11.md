## Jarvis Assistant — Model Routing + Effort Tuning

### `assistant/routing.py` (new)
- `choose_model(user_text, history)` — Sonnet 4.6 by default, escalates to Opus 4.8 for advisory/analytical questions (keyword heuristic: "should I", "recommend", "valuation", "why is X lagging", …) or long multi-part messages. Deterministic, no extra classifier call, no added latency
- `effort_for(model)` — pairs reasoning effort with tier; both default to `medium` (was hardcoded `high`). Thinking tokens bill as output → second-biggest cost dial after model choice
- Model ids + effort levels env-tunable (`ASSISTANT_MODEL_*`, `ASSISTANT_EFFORT_*`)

### `assistant/engine.py`
- Uses `choose_model` per user turn (reused across the agentic loop); chosen model emitted on the `done` event for cost attribution

### `assistant/tests/test_routing.py` (new)
- 17 cases: simple→default, advisory→escalation, long-message escalation, env override, effort pairing

**Cost impact:** routing + medium effort takes blended cost from ~$0.60/msg (all-Opus) to ~$0.35/msg; heavy usage ≈ $630/mo.

- **Fix:** skeleton only on first load (`didInitialLoad` ref); background refreshes update values in place with the table mounted. A failed refresh keeps last-loaded values with a quiet notice instead of the full error screen

## Auth — 8-Hour Session Token + Session Cookie

### `main.py`
- **Problem:** access token was hardcoded to 15-minute expiry with no refresh path; active users were logged out mid-session
- `ACCESS_TOKEN_EXPIRE_MINUTES` env var (default `480` = 8 h) now controls JWT `exp` and the Redis revocation TTL
- Cookie's `max_age` dropped so it becomes a true session cookie (cleared on browser close); JWT 8h hard cap remains the server-side authority
- Token hardening unchanged: `httponly`, `secure`, `samesite=strict`, Redis revocation on logout

## CAMS — Auto-Retry on Rate-Limit with Exponential Backoff

### `workers/cams_trigger_worker.py`
- Transient CAMS rejections ("unable to process / try again later") were caught as generic failures, indistinguishable from hard errors like "unregistered email"
- Added `CamsRateLimited` exception class; detection pattern updated to raise it instead of returning `False`
- New `trigger_cas_request_with_retry(entity, pdf_password)` — bounded exponential backoff: default 3 attempts, 60 s base delay, jitter. `CAMS_RETRY_MAX_ATTEMPTS` / `CAMS_RETRY_BASE_DELAY` env-tunable
- Hard failures (wrong email, PDF password rejected) do NOT retry
- Both callers (daily orchestrator + `manual_cas_retrigger.py`) use the wrapper; external bool contract preserved

## Logging — Remove Duplicate FileHandler Across All Workers

### All cron/systemd workers
- Root cause: workers had both a `FileHandler` writing directly to the log file AND a `StreamHandler(stdout)`; the runner (cron_wrapper or systemd `StandardOutput=append`) redirected stdout to the same file — every line logged twice
- Removed `FileHandler` from: `equity_sync_worker`, `token_refresh_worker`, `amfi_nav_worker`, `equity_price_worker`, `fx_rates_worker`, `mf_metrics_worker`
- `StreamHandler(stdout)` is now the single source; cron_wrapper also captures it for failure-alert tails
- `cas_parser` (imported, no runner) and `manual_cas_retrigger` (run manually, no redirect) intentionally keep their FileHandler

## API — Transaction Filter 500 + Realized Gains Cache

### `main.py`
- **Bug:** entity-wise transaction COUNT query reused the alias `t.transaction_type` but its `FROM` clause had no `t` alias; applying a `txn_type` filter to a specific entity raised a SQL error → 500. The "ALL entities" path was unaffected (alias-free clause). Added the alias.
- **Perf:** `_compute_realized_gains()` scanned all of `mf_transaction` on every MF holdings request; now wrapped with a Redis cache keyed by a cheap `(COUNT, MAX(id))` version stamp — new CAS transactions auto-invalidate. TTL is a memory backstop. Falls back to direct compute if Redis is down.
