## Equity Pipeline Fixes

### `workers/equity_price_worker.py` — `load_credentials()` overwrite bug
- **Bug:** `{r["broker"]: r for r in rows}` — dict comprehension kept only the last row per broker, non-deterministically. With both HHR and Rajani Corp on Dhan, whichever row came last would overwrite the other; if it had an empty token, live prices stopped updating
- **Fix:** `ORDER BY broker, CASE WHEN access_token IS NOT NULL AND access_token != '' THEN 0 ELSE 1 END` + first-wins insertion. Prefers the row with a live token when multiple entities share a broker

### `equity/token_refresh_worker.py` — DB token sync
- **Problem:** `token_refresh_worker` wrote fresh tokens to `equity_tokens.json`; `equity_price_worker` reads from `broker_api_credentials` DB table. The two stores drifted — price worker always had stale tokens after the nightly refresh
- **Fix:** Added `_sync_tokens_to_db(conn, entity_map)` — after all broker token refreshes complete, reads `equity_tokens.json` and `UPDATE broker_api_credentials SET access_token = %s WHERE broker = %s AND entity_id = %s` for each fresh token
- Both stores now stay in sync after every nightly run

## Permission Fixes

### Root cause
- `.env.local` owned `SAdmin:SAdmin` (mode 640); `www-data` (Next.js service user) was not in SAdmin group → couldn't read env vars → build and runtime failures
- `.next/build/package.json` owned by `mis-portal-svc` from a previous mis-routed build → EACCES on `npm run build`

### Fixes applied
- Added `www-data` to `SAdmin` group: `usermod -aG SAdmin www-data`
- Added `UMask=002` to `/etc/systemd/system/mis-portal.service` so new files created by `mis-portal-svc` are group-writable (664/775)
- Re-owned stale `.next/build` artifacts: `chown -R SAdmin:SAdmin /var/www/iws-portal-frontend/.next/build`
- Set setgid bit on shared directories so new files inherit group ownership
