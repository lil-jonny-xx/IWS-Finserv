## 7. Angel One — Symbol & Token Fixes

**Commit:** `3d81138` · 12:14 UTC

### Blank symbol (ADANIENT-RE)

Angel One returns `tradingsymbol: ""` for rights entitlement / partly-paid shares (e.g. ISIN `IN9423A01030` = Adani Enterprises Rights Issue). Our sync was storing `symbol = ""`, displaying as blank.

**Fix:** `angel_one.py` normalise() now uses `tradingsymbol or isin` as fallback.

### symbol_override column

Added `symbol_override VARCHAR(50)` to `equity_holding`. The sync never touches this column. Display (`main.py`, `report_generator.py`) resolves `symbol_override ?? symbol`.

Allows a manual one-time correction (e.g. `ADANIENT-RE`) that survives all future syncs.

```sql
ALTER TABLE equity_holding ADD COLUMN IF NOT EXISTS symbol_override VARCHAR(50) DEFAULT NULL;
UPDATE equity_holding SET symbol_override = 'ADANIENT-RE' WHERE isin = 'IN9423A01030';
```

### Angel One LTP showing 0

**Root cause:** `equity_price_worker.py` was calling `ltpData(exchange, symbol, isin)` — third argument must be Angel One's numeric `symboltoken`, not ISIN. API was returning no data.

**Fix:**
- `angel_one.py` stores `symboltoken` from API response into `EquityHolding.angel_one_token`
- `equity_sync_worker.py` persists it in DB; `COALESCE` so a NULL never overwrites an existing token
- `equity_price_worker.py` loads `angel_one_token` in holdings query and passes it to `ltpData()`
- Holdings with no token are skipped with a debug log

```sql
ALTER TABLE equity_holding ADD COLUMN IF NOT EXISTS angel_one_token VARCHAR(20) DEFAULT NULL;
```

### Duplicate row prevention

Old blank-symbol row (`symbol = ""`) + new ISIN-as-symbol row (`symbol = "IN9423A01030"`) would both satisfy the unique key `(entity_id, broker, symbol)` and coexist as duplicates.

**Fix:** `upsert_equity_holding()` deletes any existing blank-symbol row for the same `(entity_id, broker, isin)` before upserting.

```sql
DELETE FROM equity_holding WHERE broker = 'angel_one' AND symbol = '' AND isin IS NOT NULL;
```
